## In this lesson

- A step-by-step process for getting unstuck faster
- An example message you can copy and adapt on Discord
- Where to ask and when it's okay to reach out before everything is "perfect"

**Time:** ~10 minutes

---

Throughout your programming career, and especially while you're just starting out, you're going to need help from other people. **You are not bothering anyone** by asking questions. Instructors and classmates are here to help you learn. If you follow the guidelines below, you'll usually get useful answers more quickly.

## You don't need to have everything figured out first

These steps are a **helpful order**, not a test you must pass before you're allowed to ask. If you're stuck after 20 - 30 minutes, or you're not sure which step to try next, ask anyway and say what you've already tried. It's better to ask early than to stay frustrated for hours.

## How to ask for help

1. **Break the problem down.** Most difficult problems are actually several smaller problems that aren't so difficult. Is there a smaller piece of the problem you're working on that you could solve?

2. **Do your own research.** Go through the debugging steps you know so far (see [Debugging in JavaScript: Reading Console Errors](../../introduction-to-programming/2_javascript-and-web-browsers/1-2-1-08-debugging-in-javascript-reading-console-errors) and related lessons in Intro to Programming). Re-read or re-watch the relevant lessons on this site. Search online to see if others had the same problem.

3. **Have your problem as close to being fixed as you know how.** When something isn't going right, you might try many different things. Before you ask someone for help, get your project back to the state you think is closest to working.

4. **Demonstrate the problem.** It can be tempting to show only the problematic code and explain everything you tried, but without seeing what's going wrong, it's harder to help. Demonstrate the bug, show the part of the program you can't make work, and pull up the error message.

5. **Narrow down the problem.** Show which part of the code you think is the culprit. Explain why you think your code in its present state should work, and any ideas you have about why it doesn't.

6. **Share your hypotheses.** You'll often have ideas about what's going wrong based on your understanding and clues from your research. Share those with the person helping you—they may not be obvious from the code alone.

## Example message (Discord)

You can adapt this template in your cohort's **help and classroom** text channel (see [Installing and Using Discord](../2_getting-started-with-working-remotely/1-0-0-24-installing-and-using-discord)):

```text
Hi, I'm stuck on [lesson or exercise name].

What I'm trying to do: [one sentence]

What happens instead: [error message or unexpected behavior]

What I've tried so far:
- [step 1]
- [step 2]

My best guess about the cause: [optional — or "I'm not sure yet"]

Link or screenshot: [GitHub repo, CodePen, or screenshot if helpful]
```

During live class time, you can also ask in voice when your instructor invites questions, or message them directly on Discord if they've asked you to reach out that way.

**Note:** For **independent projects**, classmates usually cannot help with your code until you've both passed that code review. See [Academic Honesty](./1-0-0-10-academic-honesty#getting-help). Your instructor is always the right person to ask about project requirements and resubmission.
